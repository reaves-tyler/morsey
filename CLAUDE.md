# Morsey — CLAUDE.md

Gamified morse code (CW) trainer for amateur radio. Static Nuxt 4 app, no backend — all state lives in browser localStorage. Licensed AGPL-3.0-or-later (`LICENSE`; Tyler chose copyleft deliberately so the project stays free downstream — don't propose relicensing). Live at https://morsey.net/ (GitHub Pages behind a custom domain; the old https://reaves-tyler.github.io/morsey/ URL 301s there).

## Commands

```bash
pnpm install          # pnpm ONLY — npm/npx/yarn are not used in this repo
pnpm dev              # dev server on :3000
pnpm run generate     # static production build → .output/public
pnpm test             # vitest — keyer engine, Farnsworth math, generators, backup schema, CW stream decoder
pnpm run samples      # re-render the CW sample WAVs (public/samples/cw) from utils/cwSynth presets
pnpm run bench        # decoder benchmark: synthesized scenarios with known text (copy, spacing, junk, latency) + the real takes; --only <id>, --json <file>, --wav <dir> (48 kHz copies for Chrome fake capture), --cfg '<json>'
node scripts/cut-take.ts <take.wav> <out.wav> <t0> <t1> [rate]   # cut a Rec-button take into an 8 kHz fixture (windowed-sinc resample)
pnpm run og           # re-render the social preview public/og.png from scripts/og/og-image.html (playwright-core Chromium)
pnpm exec nuxt typecheck
```

pnpm 11 gates postinstall scripts: approved builds live in `pnpm-workspace.yaml` (`allowBuilds`). To smoke-test the production build locally: `python3 -m http.server 4173 --directory .output/public`.

## Stack

- **Nuxt 4** (`app/` directory layout), **Nuxt UI v4** (+ Tailwind 4 via `@import "@nuxt/ui"` in `app/assets/css/main.css`), lucide icons (`@iconify-json/lucide`)
- **No Pinia** — deliberate choice: state is plain Nuxt `useState` in composables
- Dark mode forced (`colorMode.preference: 'dark'`), zinc/emerald palette set in `app/app.config.ts`
- **Contrast**: `main.css` overrides Tailwind's `--color-zinc-500` to `#85858f` (the stock `#71717b` is 4.1:1 on zinc-950 and Lighthouse fails every label and caption on it; the override is 5.5:1 on zinc-950, 4.9:1 on zinc-900). Muted text goes no darker than `text-zinc-500`; zinc-600/700 are for borders, icons and unlit indicators only. A link inside running text carries `underline` (colour alone fails the audit). `ui.theme.colors` in `nuxt.config.ts` lists only `primary`/`error`/`neutral` — Nuxt UI emits every variant of every theme colour into the one render-blocking stylesheet, so add a colour there before using it in a `color=` prop.

| `app/utils/keyerEngine.ts` | Pure keyer engine — every sending-side state machine, no Vue/Nuxt/audio/clock dependencies (host injects `now`/`setTimer` and receives events via callbacks). Raw `tip`/`ring` contacts in; `keyType` decides meaning, like a rig's keyer menu: straight (tip only — mono-plug safe; manual timing, adaptive dit classification), bug (auto dits + manual dahs), iambic A, iambic B (Curtis-B memory latched at element start AND on mid-element squeeze). `paddleReverse` swaps roles. Timing uses `sendWpm`, NOT the receive speed. Feel knobs (all optional in `KeyerConfig`, defaults = standard keyer, surfaced as Settings → "Keyer feel"): `debounceMs`, `weight` (dah:dit, rigs offer 2.8–4.5), `dahThresholdUnits`, `adaptive` on/off, `letterGapUnits`/`wordGapUnits` (decoder patience; per-unit floors keep defaults at 450 ms/1.2 s). Unit-tested in `tests/keyerEngine.test.ts` under fake timers — change the engine, run `pnpm test`. |
| `app/composables/useKeyer.ts` | Thin adapter over the engine, module-level singleton (bar + send page share one keyer and one serial connection, which survives navigation). Wires engine events to refs + Web Audio; feeds it contacts from keyboard (straight: Space; else `[`/`]` or Ctrl keys), on-screen keys, and the USB bridge's `TIP_*`/`RING_*` serial lines. Backspace clears. `keyType` changes hard-reset the engine; `sendWpm` changes reset calibration. |
| `app/components/KeyerBar.vue` | Radio-front-panel bar fixed to the bottom of every page: collapsed strip of lit status pills (key type, REV, WPM, tone, USB, TX), pulls up into a soft-key config panel (key type, reverse, speed/tone/volume sliders, serial connect). |
| `hardware/pico-bridge/` | MicroPython `main.py` for a Raspberry Pi Pico H key→USB bridge (GP14 = tip, GP15 = ring, pull-ups, 5 ms stable-state debounce). Deliberately dumb passthrough: emits only `TIP_DOWN`/`TIP_UP`/`RING_DOWN`/`RING_UP` lines; all interpretation stays in the browser keyer. |
| `app/pages/learn.vue` | Koch trainer. Answers accepted during playback (eyes-free flow); chirp/buzz audio feedback; unlock at ≥90% over `UNLOCK_WINDOW` (30) answers. Four modes: choose grid, copy groups, words (top-100 + ham words filtered to unlocked letters), callsigns (unlocks once a digit is learned). |
| `app/pages/phrases.vue` | Tiered phrase quiz; mastery = 3 consecutive correct; next tier at 80% mastered. |
| `app/pages/send.vue` | Sending practice: char/phrase challenges validated against live decode, plus fist analysis (dah:dit ratio, consistency CV) fed by the engine's `onManualElement`. |
| `app/pages/qso.vue` | Scripted first-contact simulator (`app/utils/qso.ts` builds the steps per the standard FISTS/QRP-Labs structure); listen steps copy fields, send steps validate live decode; receive-only toggle. |
| `app/utils/cwDecoder.ts` | Pure CW **stream decoder** (PCM in → text out; no Web Audio/Vue/clock — time is counted in samples). Pipeline: quadrature mix at `centerHz` → two cascaded boxcars (triangular window, −3 dB width `bandwidthHz`, sidelobes −26 dB for QRM) → **level histogram** (one rolling 0.5 dB-binned log histogram of the last 8 s, `LevelHistogram`; every level number is a percentile of it, so nothing the gate does can feed back into it — the narrowband noise envelope is Rayleigh, measurably so on real band audio, so σ = P20 / 0.668 holds until a signal fills 80 % of the window) → gate at `max(floor + span/2, CFAR·σ, minSnrDb squelch, 0.005)` where CFAR is 4.5 σ when the band is quiet and 3.0 σ once a signal is present (a weak one sits only 4–5 σ up); the peak has a fast attack, decays only inside a key-down that lasted ≥ `MIN_MARK_MS` (otherwise a 3 ms crash drags the threshold onto the hash and the gate never recovers) and releases over 60 s, so the squelch stays where the last station put it between overs, with the histogram's upper mode pulling it back down for a weaker one; key-up edge timed at the on-level crossing so hysteresis doesn't shorten marks; 250 ms warm-up → noise blanker, plus an absolute `MIN_MARK_MS` (15 ms) rejection that **merges the silence either side of the dropped blip** instead of splitting a letter gap in two → two-cluster dit/dah tracker (log-domain 2-means over the last 10 marks, snaps on first calibration / >30 % speed change and re-classifies the character in progress; letter/word gaps tracked as their own clusters so Farnsworth spacing works) → real-time flush at the letter boundary. **Everything timing-related is clamped to physical CW**: `MIN_WPM`/`MAX_WPM` 5–60 (dit 240–20 ms), letter gap 2–20 dits, word gap 1.6–4 letter gaps, gaps over 30 dits are pauses and teach the trackers nothing. Without those the estimate has no fixed point — a shorter dit widens the window of things that count as elements, and the tracker walks itself to a 2 ms dit and 600 WPM of E and T. **Bursts** (Sept 27 2026 rework): a burst's marks/gaps are buffered raw — nothing decoded, nothing learned — until it passes the **squelch**: `BURST_ELEMENTS` (4) *and* either the histogram shows two modes ≥ 10.5 dB apart with 3–60 % in the upper one, or the burst is **strong** (median mark ≥ 8 σ) **and a tone**. Then `goLive` fits timing to the burst itself (`fitBurst`: dit/dah snap from its marks, intra/letter/word gaps from its gaps, the silence since the last printed burst as a Farnsworth tie-breaker) and decodes it from the start; after that it streams element by element. So the first letters of an over are read at *its* speed, and band hash / RTTY never drag the speed estimate (timing is learned only from live bursts; the pre-squelch shortest-mark rule assumes ≤ 20 WPM, never the prior — a 10 WPM prior used to reject every 40 WPM dit). The **gap inside a letter is measured** (`elemGapMs`, 0.5–2.5 dit), not assumed to be a dit, and the letter boundary is √(elemGap·letterGap) — a straight key leaves 1.2–1.8 dits (the TS-450S takes: 1.4). A hand-sent fist (elemGap ≥ 1.25 dit) whose "words" keep coming out one letter long gets its spacing classes promoted (letters, not words). The letter flush is suspended while a key-down sits in the noise blanker (it used to split `4` into `I U`). **Side detectors** at ±170 Hz (`process(main, side?)` — `side` is the raw input when the host pre-filters `main`) classify each burst (`burstVerdict`): `fsk` = RTTY (partner tone within 6 dB of ours in our gaps, ≥ 6 dB louder than in our marks) → never printed, `state.fsk` raised for the UI; `broad` = as loud beside the pitch as on it (static, the band returning between the operator's own muted elements) → no strong-burst path; single marks under 6 dB over the *quieter* side are dropped as crashes (a neighbour lifts only one side). Element levels are read over each element's settled middle (`settledMeans`, a detector window in from each edge) — RTTY's 22 ms bits otherwise smear the partner into our marks, which broke the verdict at 44.1 kHz only. Inside a live burst the peak decays 3× faster (`fadeFollowMs`, 40 ms) to follow HF fading. **Operator trims** (`CwDecoderConfig`, neutral by default and tested neutral): `thresholdOffsetDb`, `squelch`, `rejectRtty`, `letterBreak`, `wordBreak`, `fadeFollowMs`. `PATTERN_TO_CHAR` = `REVERSE_MORSE` + prosigns (`<SK>` `<KN>` …; characters win collisions so AR prints `+`). Unit-tested end-to-end on synthesized audio and on real recordings in `tests/cwDecoder.test.ts`. Known limits: a first word whose timing is genuinely ambiguous (H at 10 WPM ≡ TTTT at 30) follows the prior; Farnsworth letter gaps look like word gaps until a word gap reveals both classes; a letter/word gap ratio under ~1.5 (novice fists) cannot be split by timing — spacing only, letters are exact; the 10 Hz "flutter" (auroral) channel fades inside a dit and is not copied (~5 %); ITU poor fading averages ~82 % at 15 dB. |
| `app/utils/cwSynth.ts` | Deterministic CW band-audio synthesizer (`renderCw`): Farnsworth timing via `textToSchedule`, hand-sent weight/jitter and `spacing` multipliers (element/letter/word — the novice fist), QRN at an SNR quoted in a 2.5 kHz bandwidth (or a recorded `noise` bed scaled to it), QSB, ITU-R F.1487 (Watterson) multipath `fading` (`ITU_CHANNELS` good/moderate/poor/flutter: Rayleigh taps, Gaussian Doppler), one or several QRM stations, drift, keying envelope centred on the nominal edges. `renderRtty` renders 45.45 Bd 170 Hz ITA2 RTTY (what must *not* print); `characterEndTimes` gives each character's end for latency measurement (`scripts/cw-bench.ts`). `SAMPLE_PRESETS` (8 clips, easiest→hardest) back the decoder test suite and `scripts/gen-cw-samples.ts` (→ `public/samples/cw/*.wav`, excluded from the PWA precache). There is deliberately no in-app sample source any more — Tyler wants real radio audio in the UI; clips are tests-only. `encodeWav16` writes the files. |
| `app/composables/useCwStreamDecoder.ts` | Browser adapter for the decoder, module-level singleton (keeps running across navigation until Stop). Graph: source → BiquadFilter bandpass (Q = f/2·bw clamped 5–50, toggleable) → ChannelMerger ch 0, raw source → ch 1 → inline-Blob AudioWorklet that forwards 1024-sample two-channel PCM blocks to the main-thread decoder as `process(filtered, raw)` (ScriptProcessor fallback; the raw channel feeds the ±170 Hz side detectors — the pre-filter takes ~9 dB off an RTTY partner tone); an AnalyserNode on the *unfiltered* source feeds the spectrum. Sources: `line` and `mic` (both getUserMedia with echoCancellation/noiseSuppression/autoGainControl **off** — they destroy CW — but with separate device memories `lineDeviceId`/`micDeviceId`; `line` with the auto sentinel picks the first jack/USB-looking input label because the system default is almost always the built-in mic; only `mic` mutes the keyer sidetone via `useMorseAudio().setSidetoneMuted`), `file` (decodeAudioData). **Monitor** passthrough: the raw source feeds a GainNode to the destination so the operator hears the rig in headphones (plugging into a rig's headphone jack kills its speaker) — `monitor` (line/file, default on), `monitorMic` (default off: mic→speakers howls), `monitorLevel` 0–2, `outputDeviceId` applied with `AudioContext.setSinkId` where supported (Chromium). A **leveller** (`utils/monitorAgc.ts`, pure, unit-tested in `tests/monitorAgc.test.ts`) sits in front of the monitor gain as an AudioWorklet — the class is embedded verbatim via `MonitorAgc.toString()` (bound as `const MonitorAgc = …` because the bundler renames it), so it must stay self-contained: no imports, module constants or class fields. Radio-style AGC, not a speech compressor: peak target −12 dBFS, gain capped +30/−30 dB, 8 ms lookahead + 1 ms attack so a loud first dit never bursts, 1.2 s hang so band noise isn't pumped in the gaps of a transmission, 15 dB/s recovery, soft limiter. Exists because the rig's sidetone on a line input is near full scale while its receive audio is 20–30 dB down (Tyler was riding the volume between over and back). `monitorAgc` setting (default **off** since Sept 27 2026 — a stored "on" from the old default is migrated off once via `levellerDefaultOff`; its switch works whether or not the Morsey monitor is on, since it also shapes recordings and Tyler monitors through the Focusrite's Direct button) toggles it; `monitorGainDb` is the live readout. Note what this does to the operator's ears: between overs the leveller runs to its +30 dB cap and lifts band noise that is really at −50 to −65 dBFS up to around −30, so the band sounds far noisier in headphones than the decoder's input is — the decode page says so, because mistaking that for a noisy *signal* is what sent the Sept 19 2026 decoder debugging down the wrong path. Device labels are blank until the first grant, so `requestDevicePermission()` probes getUserMedia once and re-enumerates; Chromium's `default`/`communications` alias devices are filtered out (the id `default` collides with the sentinel). A second tap on the **leveller's output** (before the monitor gain, so the volume slider is not baked in) feeds the **recorder** — an export is the audio the operator actually heard; switch the leveller off to capture the rig's own levels, which is how to cut a decoder fixture — (`recordingState` idle/recording/paused; `startRecording` starts or resumes, `pauseRecording`, `exportRecording` → 16-bit WAV Blob at the context rate and ends the take, `discardRecording`; capped at ~10 min, pausing when full) so a take documents the session and real on-air misses can be replayed through the decoder tests. Settings persist to localStorage `morsey-decode-v1`. The **terminal text is a log tail** (Tyler: "literally the live logtail"): persisted to `morsey-decode-log-v1` (last 20k chars), kept across Stop/Start, level resets and reloads; a new session and 5 s of silence (`IDLE_NEWLINE_MS`, decoder-time from `onKey`) each start a new line if the current one has text; **only** `clear()` empties it. `resetLevels()` re-learns floor/peak/σ (decoder `resetLevels`) without touching timing or text — the "Reset levels" button on the meter, for after a volume/gain change. |
| `app/utils/cwHighlight.ts` + `app/components/CwHighlightedText.vue` | Syntax highlighting for the decode terminal. `highlightCw(text)` tokenizes decoder output into `prosign` / `qsignal` / `rst` / `abbr` / `callsign` / `text` / `unknown` tokens with a hover tip (dictionary = `PHRASE_TIERS` + `COMMON_ABBREVIATIONS` + extra Q-signals + `PROSIGN_MEANINGS`; callsign regex covers 1x1–2x4 with portable designators). The component renders the tokens and one fixed-position, Teleported tooltip placed from the hovered span's rect (instant, unclipped by the scrolling terminal). |
| `app/utils/cwSplit.ts` | **Run-on guesses.** The stream decoder prints `*` for a pattern that matches no character and hands the raw pattern along in `onCharacter(ch, pattern)`; the *adapter* (not the engine — the decoder is untouched) writes it into the log as `{-.-.--.-}` instead of the star, so the elements that were heard are never lost. `splitPattern` enumerates every cut of that pattern into known characters (≤ 5 parts, ≤ 24 elements), fewest cuts first, letters/digits before punctuation; `unknownToken` in `cwHighlight.ts` promotes readings the highlighter itself recognises — a dictionary word, Q-signal, RST, prosign, or a callsign whose prefix is in `CALLSIGN_ENTITIES` (the bare callsign regex matches nearly anything, P9Y included) — so W1AW run together reads as W1AW, not P9Y. ## SEO

The landing page (`index.vue`) keeps a descriptive H1 + one-paragraph pitch above the dashboard; the longer method prose and the FAQ (also emitted as `FAQPage` JSON-LD) live on `/about` — keep answers honest (no inflated learning-time claims). `@nuxtjs/sitemap` + `@nuxtjs/robots` (config under `site`/`sitemap`/`robots` in `nuxt.config.ts`) prerender `/sitemap.xml` and `/robots.txt`; AI search crawlers are explicitly allowed. `public/llms.txt` is the AI-search summary — update it when features change. No hidden text or keyword stuffing, ever: it risks the whole domain.

## Deployment

Push to `main` → `.github/workflows/deploy.yml` → `pnpm exec nuxt build --preset github_pages` with `NUXT_APP_BASE_URL=/` → GitHub Pages. Pages source is "GitHub Actions"; custom domain `morsey.net` is set in repo Settings → Pages (not a CNAME file — Actions-sourced sites keep it in settings). DNS lives at Cloudflare: four apex `A` records to the Pages IPs plus `www` CNAME → `reaves-tyler.github.io`. The base URL must stay `/` while the custom domain is active; reverting to `/<repo>/` would break asset paths.

Icon gotcha: `icon.provider: 'iconify'` lives under `$production` in `nuxt.config.ts` — prerender fetches icon data from the Iconify API (the static preset has no server icon endpoint) while browsers use the scanned client bundle. Do **not** hoist it to top level: dev must keep the default local server provider or it produces `[Icon] failed to load icon` warnings offline.

PWA gotchas (@vite-pwa/nuxt): the manifest link requires `<NuxtPwaManifest />` in app.vue; the module's own SW registration doesn't fire on the prerendered site, so `app/plugins/register-sw.client.ts` registers explicitly (base-URL aware). Workbox config in `nuxt.config.ts` MUST keep the `manifestTransforms` filter (the `/200`, `/404` precache entries return non-200 and abort the entire SW install — on GitHub Pages too) and `navigateFallback: null` (a fallback shell hijacks online navigations; the default `/` fallback also breaks install with non-precached-url). Verify SW health via CDP `ServiceWorker.workerErrorReported`, not just `register()` resolving.

## Domain rules (do not "fix" these)

- Character speed stays fast (20 WPM default) — Koch method forbids slow characters; only the *spacing* (effective WPM) stretches, per the ARRL Farnsworth formula in `morseTimings`.
- Answer grids stay in fixed Koch order — the challenge belongs in the ears, not button hunting.
- Sending timing is independent of listening speed and adaptive to the user's fist.
- Character codes / prosigns / Koch order are validated against ITU-R M.1677-1 and LCWO's published sequence — change only with a reference in hand.

## Verification

- **Keyer timing/decode logic**: `pnpm test` — deterministic Vitest suite over the pure engine with fake timers (runs in CI before every deploy). Any change to element timing, iambic behavior, classification, or gap policy belongs there first.
- **Stream decoder**: also `pnpm test`, and `pnpm run bench` before/after any decoder change (synthesized scenarios with ground truth + every real take; a change that lifts the synthetic numbers but costs a real-take phrase or adds junk is a regression — the fading work of Sept 27 2026 rejected three such variants). `tests/fixtures/ts450s/` is a Kenwood TS-450S on the CQ WW RTTY weekend: what the operator heard as "insanely fast machine CW" through the CW filter was **RTTY** (PP5KP, HI3LT — confirmed by Baudot-demodulating it), plus the operator's own straight-key CQ at 885 Hz, a minute of static, and `ts450s-narrow-filter-cq.wav` — the sidetone only ~8 dB over the hiss the rig's narrow CW filter piles onto the same pitch, which prints nothing at the default 100 Hz and copies at 40 Hz (the decoder does not yet narrow its detector to the sender's speed; that fixture is the target when it does). When nothing prints, the decode page's amber "Holding back — …" line (`state.hold`, also logged as `[decode] holding:`) says which gate refused the keying; the raw 48 kHz takes stay out of git. — `tests/cwDecoder.test.ts` synthesizes band audio (`utils/cwSynth.ts`, seeded) and asserts decoded text / speed tracking across speeds 8–45 WPM, Farnsworth and hand-sent spacing, SNR 3–40 dB, QSB, QRM, drift, hard keying, block-size and sample-rate independence, plus every shipped sample preset within its difficulty budget, plus **real radio takes**, all recorded with the decode page's Rec button and downsampled to 8 kHz for `decodeWav16`. `tests/fixtures/k5/` is a Quansheng UV-K5 loopback (a novice straight-key fist, so those tests assert signal path and letters, not spacing — the sender's 4–7-dit letter gaps overlap word gaps and no timing rule can separate them, tried and reverted Sept 2026). `tests/fixtures/ft991a/` is the band as it really is — ten one-minute cuts off a Yaesu FT-991A on 40 m, 11–29 WPM, QSB, QRM, static, dead stretches between overs and the operator's own QSK transmissions muting the receiver. Each is asserted two ways: the phrases that were really sent must be copied (matched with spacing removed — several of those senders leave 5–7 dits between letters), and the junk around them is bounded by the share of single-element characters (E and T) and a character count. Those bounds are the regression that matters: before Sept 2026 one 8-minute take printed 1066 characters of which 88 % were E and T. Every one of those takes is a comfortable signal (14–37 dB over the noise in 2.5 kHz — that is what was on the band), so `991a-band-noise.wav` (40 s of the same rig on a dead 40 m; measured stationary and Rayleigh to within 0.5 dB at every quantile, static crashes in the tail) is mixed into the IOTA CQ at a stated SNR to test weak copy on **real** static. Real band noise is shaped — the rig's CW filter peaks it at 500–600 Hz, right on the detector — so it costs more than white noise at the same quoted SNR: exact copy holds to 9 dB at the default 100 Hz bandwidth and to 6 dB with the filter at 40 Hz, and below 3 dB the requirement is only that it degrades instead of running away. Tune thresholds there, not by ear. New takes: record at a level near −20 dB on the meter, send a text agreed in advance, downsample 48 k→8 k with a windowed-sinc lowpass before decimating. `playwright-core` is a devDependency for driving the built site headlessly (Chrome flags `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav> --autoplay-policy=no-user-gesture-required` feed a WAV into the live input unattended — render it at 48 kHz with `renderCw`/`encodeWav16`; Chrome's fake capture stays silent on the 8 kHz clips in `public/samples/cw/`).
- **Lighthouse / PageSpeed**: run it locally before trusting a PSI number (two PSI runs of the same deploy differ by 5–10 points). Serve `.output/public` through a gzip-capable static server (plain `python3 -m http.server` sends the raw 800 KB and scores ~60) and run `pnpm dlx lighthouse http://localhost:<port>/ --form-factor=mobile --screenEmulation.mobile --throttling-method=simulate --only-categories=performance,accessibility,best-practices --chrome-flags="--headless=new --no-sandbox" --output=json --output-path=<file>` with `CHROME_PATH` pointing at a playwright Chromium (`~/.cache/ms-playwright/chromium-*/chrome-linux/chrome`, not the headless shell). Live `morsey.net` scores the same as the local build. What is left on the landing page is structural: the one render-blocking Tailwind stylesheet (~26 KB gz), ~280 KB gz of JS of which ~150 KB is the Vue/Nuxt/Nuxt UI/icon floor, and GitHub Pages' fixed `cache-control: max-age=600` on hashed assets — the cache lifetime, HSTS, CSP and the other header audits can only change by putting a proxy (Cloudflare, SSL mode Full (strict) or the Pages HTTPS redirect loops) in front of Pages. Lazy-hydrating `KeyerBar` was tried Oct 2026 and reverted: Nuxt still modulepreloads an SSR-rendered async component's chunk, so bytes and score did not move.
- **Search Console**: every bare URL (`/learn`) 301s to the slashed one and is filed under "Page with redirect" for good, as are `http://`, `www.` and `http://www.` of the home page — that bucket is informational and never empties; the indexed count should equal the sitemap's eight URLs. A "Redirect error" on a URL that curls clean today (`curl -sSIL`) is a stale crawl (the Sep 5–6 2026 ones were from the days of the domain move) — the fix is "Validate fix" in Search Console, not code.
- **Everything else**: verify in the real app. Serve `.output/public`, then drive with playwright-core (`~/.cache/ms-playwright/chromium_headless_shell-*`) — keyboard events with realistic hold/gap timings exercise the trainer and keyer end-to-end. Always check the browser console for errors and run `pnpm exec nuxt typecheck` before committing.
